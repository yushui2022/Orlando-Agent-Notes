# 官方资料与版本口径

[学习目录](../README.md) · [术语与自测](术语与自测.md)

核对日期：2026-10-07。本文档区分产品机制、架构推导和实验结果，避免把一个版本的能力写成所有 MQ 的共同保证。

## 版本与实验口径

| 内容 | 使用口径 |
|---|---|
| Kafka | 以 4.1 官方文档解释常规 consumer group、位点、事务和确认；不是对所有新消费模式的概括 |
| RabbitMQ | 以 4.1 文档和官方教程解释 AMQP 0-9-1 工作队列；Compose 为 4.1-management 可变标签，运行时记录 digest |
| Pika | 客户端固定 1.3.2；本地处理函数测试与 Broker 联调分开记录 |
| RocketMQ | 5.x 文档体系中的事务消息概念；未在本仓库部署或压测 |
| Redis | 官方 Streams 消费组与接管命令；未在本仓库部署或压测 |
| 容量公式 | 基于明确假设的估算，无产品性能排名 |
| Agent 架构 | 本系列的设计示例，不宣称是任一沙箱产品的实际实现 |
| 实验结果 | 以[验证记录](../实战/README.md)为准；单机进程崩溃测试不等于多副本容灾测试 |

## 与原有学习仓库的关系

[How-to-learn-Agent-Sandbox](https://github.com/yushui2022/How-to-learn-Agent-Sandbox)提供执行隔离、生命周期、多 Agent 通信与失败传播的学习背景。本系列在第 06 篇给出了到具体关联文章的链接，未改写该仓库，也没有把其案例中的产品能力推广为 MQ 的通用能力。

本系列的故障时间线、教学代码、容量算例和练习题是为本仓库编写的解释与实验设计。产品名称、参数和保证范围应回到对应版本的官方资料核对；实际生产决策还需要在自己的消息大小、负载、持久化与延迟要求下验证。
